还有个连带影响：复制失败时，后面的被领计数也不会发（代码里计数是在复制成功后才发的），所以这些失败的领取在统计里是看不到的。

**修法也很小，只动一个文件** `dist/muse/index.html`，不改计数、回报、排序、下架任何逻辑：

```
async function copyText(text) {
  if (navigator.clipboard && navigator.clipboard.writeText) {
    try { await navigator.clipboard.writeText(text); return true; } catch (e) {}
  }
  try {
    const ta = document.createElement('textarea');
    ta.value = text; ta.setAttribute('readonly', '');
    ta.style.cssText = 'position:fixed;top:0;left:0;width:1px;height:1px;opacity:0;';
    document.body.appendChild(ta);
    ta.select(); ta.setSelectionRange(0, text.length);
    const ok = document.execCommand('copy');
    document.body.removeChild(ta);
    return ok;
  } catch (e) { return false; }
}
```

### 11:14 Brio（支线：Muse邀请码互助网站建设）
查到了，是两个原因叠在一起，都在代码里确认了：

**原因一：卡片复制后列表会全量刷新重排**
卡片上点“一键复制”后，代码会调 `refreshAll()` 把整个列表从服务器重新拉一遍重绘。而复制本身会让这个码的被领次数 +1，排序分一变，这张卡就往下掉，经常直接掉出当前这一批。用户从 Muse 回来，卡已经不在原来那个位置了，卡上的成功 / 失败回报按钮自然点不到。按钮上那个“✓ 已复制”也被重绘抹掉了。

**原因二：“一次领一个”领到的码只存在内存里**
全站搜了一遍，没有任何 `localStorage` / `sessionStorage`。领到的码只放在 JS 变量里，页面一刷新就丢 — 而手机上切去 Muse 兑换、再切回浏览器，页面被重载是最常见的情况。一重载，领取面板直接打回初始的“领一个邀请码”按钮，下面的“兑换成功 / 没兑上”回报区整个消失。而且回报接口要求必须有这个领取对象，没它连提交都发不出去。

所以真实用户的遭遇就是：复制完去兑换，回来想反馈时，码已经找不到了。

**修法（不动计数、排序、下架规则）：**
1. 卡片复制后不再全量刷新列表，只就地改该卡的“已被领 N 次”数字，不重排、不换页，卡 stays 在原地，回报按钮一直在；
2. “一次领一个”领到的码存到 `localStorage`（码 + claimId + 时间），进页面时如果有还没回报的领取记录，自动恢复领取面板和回报区；回报提交成功后清除，超过 48 小时（兑换窗口过了）也清除。
